# ZOZA hybrid v1
This is not CAPS2 and does not promise exact agreement with any hosted service.
References: https://lichess.org/page/accuracy and the source linked there at
https://github.com/lichess-org/lila/blob/2e653ad1e2b9fad31b4a092394019ef8fafdedb8/modules/analyse/src/main/AccuracyPercent.scala
Chess.com overview: https://support.chess.com/en/articles/8708970-how-is-accuracy-in-analysis-determined

Engine scores are normalized to White once in the UCI adapter. Numeric mate values are retained as mate, not displayed as centipawns. For this metric only, mate maps to signed 1000cp and ordinary cp is clamped to [-1000,1000]. Missing scores are excluded, never replaced by zero.
Move accuracy uses the public exponential formula with the source's +1 uncertainty bonus; improvements return 100. Book labels do not override accuracy and unanalysed Book moves contribute no score.
Weights use population standard deviation of sliding Win% windows, sized floor(plies/10), clamped 2–8; weights clamp 0.5–12. The aggregate is 50% weighted mean plus 50% harmonic mean. A zero accuracy has harmonic limit zero, not an arbitrary floor of 10. Missing/invalid scores yield no aggregate. We report partial coverage explicitly.
Differences from a server result: actual root evaluation (including custom FEN), local Stockfish searches, engine/depth variation, explicit missing-data handling, and separate local classification rules. The same aggregation is used for phase samples and the radar; this does not make phase ratings calibrated Elo. Computation is our independent implementation of the described mathematics.

## v11 historical classifications and game performance (superseded by v12)
Miss is a local heuristic: previous opponent move raises the current mover's white-normalized chance index by at least 12 percentage points, current chance index is at least 68, and the reply loses at least 10. Book and top-engine choices take precedence. All three positions must have comparable engine identity when known. This is not Chess.com's classification formula.

Game performance is an **experimental uncalibrated estimate**, not Elo or Chess.com Game Rating. It uses the user-proposed blend `0.55*base + 0.30*(3100*exp(-0.011*max(5,ACPL))) + 0.15*(base+(accuracy-75)*16.5)`, rounded to 50 with minimum 200. It requires a recorded positive player rating, at least three moves, and complete accuracy coverage. ACPL includes only before/after cp pairs (mate excluded); a separate label shows this scope. It must not be used for ranking or fair-play decisions.

Account exercises analyze at 1200 ms/position with MultiPV 2 and recheck candidate errors at 3000 ms/position. Solutions remain engine suggestions; equal alternatives may exist. Completed positions save locally and resume with the same engine. Archive loading follows supported API pages; unavailable/private games cannot be included. Opening-leak statistics group longest-prefix matches into named opening families, count own mistakes in the first ten full moves, and display analyzed coverage. No Book move is automatically granted 100 accuracy.

## v12 current methods
Hybrid remains the default. The selector also offers **ZOZA Strict (experimental)**, not CAPS2. Its per-move effective loss is max(chance-index loss, 0.082 × cp loss). CP loss is used only for finite before/after CP values, never synthetic mate-to-CP conversions. Accuracy = clamp(103.1668 × exp(-0.068 × effectiveLoss) - 3.1668, 0, 100). Neither Book nor Best automatically grants 100. Missing or mismatched-engine evaluations remain missing. For mate pairs, only the chance component is available.

Strict weights = (accuracy < 75 ? 1.65 : 1) × (1.6 - abs(pre-move chance - 50)/50). Aggregate is half weighted mean plus half harmonic mean. Any exact zero gives a harmonic component of zero; there is no score floor that invents credit. Comparison recalculates both methods from identical saved evaluations and cannot establish superiority or Chess.com equivalence.

Classification v2 uses the requested CP/chance thresholds, with Best restricted to the actual engine choice. Great requires a distinct equal-depth alternative gap >=220 cp, pre-move chance 20–78%, and no immediate same-square recapture. Brilliant retains the legal material-sacrifice heuristic and chance >=48. Miss requires a previous opponent chance loss >=9 or CP loss >=110, current chance >=55 and reply loss >=7.5 chance or >=95 cp. Otherwise Blunder: chance loss >=18 or cp loss >=240 with chance >=15; Mistake: chance loss >=9.5 or cp loss >=115 with chance >=12; Inaccuracy: chance loss >=5 or cp loss >=60. Excellent: chance loss <=2.2 and known CP loss <=28, else Good. These are local labels, not proof of a forced result.

Current experimental overall game rating: base + (accuracy-75)×18.5 + Brilliant×65 + Great×35 - Blunder×75 - Miss×35 - Mistake×25, rounded to 50 and floored at 250. Requires a recorded positive baseline and at least three fully analyzed own moves. No default 1200; no calibration claim. For example, base 1200, accuracy 62, two Blunders and no other counts gives 800 (not 1050).

Phase samples continue to use the same selected accuracy aggregation. Position-based phase heuristic: <=6 non-pawn/non-king pieces means Endgame; otherwise first 10 full moves Opening; otherwise Middlegame. This is approximate. Tactical sample is independently checks/captures/promotions and is not synonymous with Middlegame. Endgame does not measure strategy skill. Phase rating uses the previously documented base+(phase accuracy-80)×18 heuristic, with full coverage and >=3 moves required.

## v13 evidence correction
The visible coach name is ZOZA (زوزا). Accuracy now prefers a finite played-move evaluation from the parent's MultiPV lines when root depth and engine identity match the parent's best evaluation. Both before/after position evidence must exist and not have conflicting engine identity. This makes the comparison consistent with move classification and avoids attributing some differences between searches to the player's move. If unavailable, the before/after position pair remains in use and its depth mismatch is displayed. Equal depth alone does not guarantee equal search reliability. Raw engine data is unchanged.

Strict remains an explicitly harsher experimental measure. Its combination of CP loss, steep decay and extra error weights can depress scores substantially; being closer to a desired number would not establish validity. Hybrid v2 is not calibrated to Chess.com and can increase or decrease after evidence corrections. A per-move JSON audit supports investigating actual games; no comparative accuracy superiority has been established.
